# 메뉴의 새 소식 표시

- ☰ 버튼: 확인할 소식이 하나라도 있으면 빨간 점(`#E53935`, 8px).
- Drawer: 초대·알림·공지사항·문의에 숫자 배지. 0건은 숨기고 100건 이상은 `99+`.
- 초대: 현재 계정 이메일로 온 유효한 대기 초대. 수락·거절·취소·만료·공간 삭제 건은 제외.
- 알림: 현재 공간 접근 권한이 있고 아직 읽지 않은 일정 알림. 기존 Firestore 읽음 기록 사용.
- 공지: 아직 상세를 확인하지 않은 공지. 최초 적용 시 기존 공지도 미확인으로 표시.
- 문의: 내 문의 중 확인하지 않은 관리자 답변이 있는 문의 수. 여러 답변도 문의별 1건.

공지·문의는 목록이나 Drawer를 열기만 해서는 읽음 처리하지 않는다. 상세가 표시된 뒤 표시한 내용의 버전을 서버에 보내 읽음 처리한다. 이후 새 답변이나 공지 내용 변경이 있으면 다시 표시한다. 삭제된 공지·답변은 집계에서 제외한다.

## 서버와 저장소

- `GET /activity/badges`: 인증한 계정의 집계. 개별 조회 실패는 `null`로 반환하며 앱은 마지막 확인 숫자를 유지한다.
- `POST /activity/notices/{admin_id}/{notice_id}/read`
- `POST /activity/inquiries/{question_seq}/read`
- POST 본문: 상세 응답의 `badge_token`을 `{"token":"..."}`으로 전달. 표시 이후 내용이 달라졌으면 409로 새 내용을 미리 읽음 처리하지 않는다.
- 공지·답변 읽음 기록은 Firestore `activity_reads/{UID의 해시}/items/{항목 키의 해시}`에 저장한다. MySQL 스키마 변경은 없다.
- 서버의 기존 Firebase Admin 키/IAM 권한을 사용한다. 앱은 Firestore에 직접 접근하지 않는다. `firestore.rules`에 서버 전용 경로 예시를 추가했다. 운영 중 포괄 허용 규칙이 있다면 이 경로도 공개되지 않도록 기존 규칙을 함께 확인한다.

앱이 열린 동안 30초마다, 앱 복귀 시, 메뉴 버튼을 누를 때 갱신한다. 상세 읽음 처리 및 메뉴 화면에서 돌아온 뒤에도 갱신한다. 푸시나 실시간 구독은 아니므로 외부에서 도착한 새 소식은 다음 조회 시 반영된다. 조회 실패 시 정상 0건으로 처리하지 않는다. 읽음 저장 실패 시 상세 상단에 재시도 버튼을 표시한다.

## 확인 순서

서버를 재시작하고 앱을 Hot Restart한다. 다른 계정에서 초대하거나 관리자 웹에서 공지·답변을 등록한다. 대상 계정으로 메뉴를 열어 숫자와 빨간 점을 확인한다. Drawer를 열고 닫아도 유지되는지, 각 상세를 확인하면 해당 숫자만 줄어드는지 확인한다. 앱 재실행·계정 전환·다른 기기에서도 읽음 기록이 구분되는지 확인한다.
