# 공간·메모·투약일지 알림

기존 Firestore `schedule_notifications` 수신함과 FCM 발송 worker를 재사용합니다. MySQL 테이블·컬럼 변경은 없습니다.

| 작업 | 수신자 |
| --- | --- |
| 새 가족 입장(초대 수락) | 입장한 본인 제외 현재 가족 |
| 주보호자 이전 | 이전을 실행한 기존 주보호자를 제외한 현재 가족 |
| 공간 탈퇴 | 탈퇴한 본인을 포함한 당시 가족 |
| 공간 강퇴 | 강퇴를 실행한 주보호자를 제외한 당시 가족(강퇴 대상 포함) |
| 새 메모 작성(사진 포함) | 작성자 제외 현재 가족 |
| 약 추가 | 추가한 사람 제외 현재 가족 |

메모 수정·삭제, 약 수정·삭제, 복용 완료·취소는 이번 범위에 포함하지 않습니다. 기간으로 약을 추가해도 요청 한 번에 알림 하나를 준비합니다. 계정 정리 worker 내부에서 수행하는 참여 종료는 이번 공간 탈퇴 알림 대상이 아닙니다.

## 저장 및 발행

- `python/features/notifications/space_events.py`에서 업무 commit 전 pending 알림을 준비합니다. 알림 저장소 연결 실패 시 업무를 확정하지 않습니다.
- commit 후 별도 MySQL 연결로 원본의 확정을 확인하고 published로 전환합니다. 발행 실패는 기존 통합 worker의 pending 재시도 경로에서 처리합니다.
- published 전환은 트랜잭션으로 처리해 API·worker가 함께 실행되어도 푸시 큐를 재등록하지 않습니다. 기존 발행·FCM 루프와 실행 명령은 그대로 사용합니다.
- 주보호자 이전의 미발행 알림은 대상자가 여전히 주보호자인 경우에만 재시도합니다.
- 목록·배지·읽음·개인 삭제는 기존 알림 API를 사용합니다. 새 Firestore 색인은 필요하지 않습니다.

## 권한과 개인정보

알림에는 메모 내용·약 이름·건강정보를 넣지 않습니다. 탈퇴·강퇴 대상은 본인에게 발행된 참여 종료 안내만 읽을 수 있습니다. 다른 알림은 현재 공간 참여를 재검사합니다. 공간이 삭제되면 현재 가족의 안내도 숨깁니다.

새 유형을 누르면 안내 팝업을 표시합니다. 일정 상세로 보내거나 종료된 공간을 자동 선택하지 않습니다. 현재 동작은 해당 메모·약 상세로 바로 이동하는 방식이 아닙니다.

## 최소 검증

`python -m unittest python.tests.test_space_events -q`

외부 MySQL·Firestore·FCM을 모킹하여 수신자, 중복 발행, rollback 원본, 개인 삭제, 참여 종료 후 접근 범위를 확인합니다. 실제 두 계정으로 앱 내 알림·기기 푸시는 별도 확인이 필요합니다.


## 상세 화면과 돌봄 메뉴 빨간 점

공간·메모·투약일지 알림은 `CareNotificationDialog`에서 공통 테마의 아이콘, 공간 카드, 설명, 발생 시각과 확인 버튼으로 표시합니다. 공간 삭제 안내도 같은 구성을 사용합니다. 긴급 일정은 기존 일정 상세의 수락·재수락 버튼을 유지하고 긴급 안내 배너만 추가합니다.

돌봄 공간 홈의 메모·투약일지·일정 아이콘에 해당 공간의 미읽음 알림이 있으면 빨간 점을 표시합니다. 채팅의 숫자 배지는 유지합니다. 미읽음 ID는 기존 `/activity/badges`의 알림 순회에서 함께 계산하므로 별도의 전체 Firestore 조회는 추가하지 않습니다. DB 변경은 없습니다.

메뉴를 연 순간의 알림 ID를 고정하고 목록 조회가 성공한 뒤 해당 ID만 서버에서 권한 재검사·읽음 처리합니다. 목록 로딩 실패나 읽음 저장 실패 시 점을 지우지 않습니다. 메뉴에 머무는 동안 도착한 새 알림은 미리 읽지 않습니다. 해당 알림을 알림함에서 읽거나 삭제해도 점은 다음 배지 갱신에 반영됩니다. 앱 내 알림이 생성되기 전의 과거 기록을 소급해 미확인 항목으로 표시하지는 않습니다.
