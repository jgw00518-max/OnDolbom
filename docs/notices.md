# 사용자 공지사항 조회

공통 Drawer의 알림과 문의 사이에 공지사항 메뉴를 배치한다. 목록은 최신순 30건이며 이전/다음 페이지·새로고침·상세 조회를 제공한다. 본문은 일반 텍스트로 표시한다.

관리자 웹의 기존 `create_notice`와 같은 컬럼·복합 키 `(admin_id, notice_id)`·논리 삭제 조건을 사용한다. DB 구조나 관리자 코드는 변경하지 않는다.
사용자 앱은 기존 `API_BASE_URL`의 사용자 서버로 요청하므로 관리자 웹 서버 주소를 추가할 필요가 없다. 양쪽 서버가 동일 MySQL DB를 사용해야 한다.

- `GET /notices?limit=30&offset=0`: `{items: [...], has_more: bool}`
- `GET /notices/{admin_id}/{notice_id}`: 공지 제목·본문·등록일·수정일
- 모든 요청은 Firebase ID 토큰 필요. 사용자 서버에는 공지 쓰기 API를 제공하지 않는다.
- 삭제 공지는 제외하며 없는 상세는 404, DB 오류는 503으로 안내한다. 실패 시 무한 자동 재시도하지 않는다.

확인: 관리자 웹에서 공지 등록 → 사용자 Drawer의 공지사항 → 새로고침 → 제목 선택 → 상세 확인. 수정 후 상세 새로고침, 삭제 후 목록·상세에서 제외되는지도 확인한다.
자동 테스트는 DB/HTTP 대체 객체를 사용하며 실제 공지를 등록·수정·삭제하지 않는다.
