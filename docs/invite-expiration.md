# 가족 초대 만료·재요청

- 초대는 SMTP 발송 성공 시각(`invite_at`)부터 7일 동안 유효하다. 판정은 MySQL `CURRENT_TIMESTAMP`를 사용하며, 정확히 7일이 되면 만료다.
- 기존 받은/보낸 목록 조회와 수락·거절·취소 API가 만료를 확인한다. 별도 worker나 새 테이블은 필요 없다. 앱에 열린 과거 목록은 새로고침하거나 다시 들어오면 최신 상태가 표시되며, 서버는 작업 직전에도 유효기간을 확인한다.
- 받은 만료 초대는 만료 안내만 표시하고 수락·거절 버튼을 제공하지 않는다.
- 보낸 목록은 `can_resend`가 참인 만료 초대에 `재요청`을 표시한다. 원래 발신자가 현재 공간의 주보호자인 경우에만 허용한다. 다른 주보호자는 기존 가족 초대 화면에서 새 초대를 보낼 수 있다.

## API와 저장 흐름

`POST /invites/{invite_id}/resend` — Firebase 인증 필요, 요청 본문 없음, 정상 응답 201.

1. 원래 발신자와 현재 공간의 주보호자 권한을 확인한다.
2. 공간 → 원본 초대 순서로 잠그고 만료 여부를 다시 확인한다.
3. 기존 초대의 공간·이메일로 새 UUID의 초대를 생성한다. 기존 만료 초대는 보존한다.
4. 이미 참여 중인 가족이거나 같은 공간·이메일에 유효/발송 중인 초대가 있으면 409로 차단한다. 같은 공간 잠금으로 동시 재요청도 직렬 처리한다.
5. `발송대기`를 확정한 뒤 기존 `send_invite_email`로 이메일을 보낸다.
6. 성공하면 새 초대의 `invite_at`을 갱신하고 `대기`로 확정한다. 실패하면 `발송실패`, `email_sent: false`로 응답한다. 원본 만료 초대에서 다시 재요청할 수 있다.

기존 `POST /invites`와 메일 발송·중복 검사를 공유한다. 응답의 `invite_id`는 새 초대 ID이며 원본 ID를 재사용하지 않는다. 목록 응답에는 `expires_at`, 보낸 목록에는 서버가 계산한 `can_resend`가 추가된다. SMTP 설정은 기존 가족 초대와 같다.

## 검증

- 서버: `python -m unittest python.tests.features.test_invite_resend`
- 앱: `flutter test test/invites_design_test.dart test/vm/invite_resend_test.dart`
- 자동 테스트에서는 DB와 SMTP를 모의 처리한다. 실제 기존 초대 날짜를 테스트 목적으로 변경하거나 이메일을 발송하지 않는다.
- 실제 확인: 이미 만료된 본인 초대의 보낸 초대함에서 재요청 → 새 초대와 메일 확인 → 수신자의 받은 초대함 새로고침 → 기존 만료 초대의 버튼 없음/새 초대의 수락 버튼 확인.
