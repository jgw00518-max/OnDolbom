# 계정 비활성화 · 재활성화 · 30일 후 최종 탈퇴

## 확정 정책
- 탈퇴 요청 시 user.withdrawn_at에 DB 현재 시각을 기록한다. 이름·전화번호·이메일·Firebase 인증 계정 및 모든 서비스 데이터는 30일 동안 보관한다.
- 30일 동안 돌봄 공간 참여와 담당 일정을 그대로 유지한다. 서비스 접근과 푸시는 기존 withdrawn_at 검사로 차단한다.
- 주보호자는 이전 또는 공간 삭제 후 비활성화를 요청할 수 있다.
- 반복 탈퇴 요청으로 기존 탈퇴 일시를 연장하지 않는다.
- 탈퇴 안내창에 30일 유예·재활성화 가능·최종 개인정보 삭제·공유 기록 익명 표시를 안내한다.

## 로그인 및 재활성화
- Firebase 인증은 본인 확인에 필요하므로 유예기간 중 SDK 계정 자체를 disabled 처리하거나 삭제하지 않는다. 서비스 로그인만 차단한다.
- GET /auth/me: 비활성 계정은 403 detail.code=account_inactive, reactivation_until, can_reactivate를 반환한다. 앱은 공간 목록 대신 ‘비활성 계정’ 화면을 표시한다.
- POST /auth/account/reactivate: 검증된 토큰의 UID만 사용한다. DB 행 잠금 후 DB 시각으로 30일 미만일 때만 withdrawn_at=NULL로 변경한다.
- 재활성화 시 사용자 정보를 다시 불러와 기존 참여·담당 상태로 진입한다. 자동으로 탈퇴를 취소하거나 기한을 연장하지 않는다.
- 정확히 30일이 되는 시점부터 재활성화는 410으로 거절한다. 앱의 시계나 worker 지연과 무관하다.

## 최종 정리 worker
- 기존 명령: python -m python.features.schedules.reminder_worker
- 기존 알림 작업과 별도 스레드에서 시작 시 및 이후 1시간마다 최대 20개 계정을 검사한다. 공유 환경에서는 대표 1명만 실행한다.
- 30일 경과 후 첫 성공한 검사에서 최종 정리한다. worker 중지·외부 장애 시 실제 정리는 지연되지만 재활성화는 허용되지 않는다.
- 공간 참여를 종료하고 미완료 일정 담당을 해제한다. 완료 이력과 공동 작성 기록은 보존한다.
- 개인 문의·답변 및 개인 채팅 읽음 기록을 제거하고, 초대 이메일을 식별할 수 없는 대체 주소로 바꾼다.
- 개인 Firestore 수신 목록 연결·읽음 문서·푸시 기기 정보·현재 키로 식별되는 이메일 OTP 문서를 제거한다. 공유 알림 작성자 표시를 ‘탈퇴한 사용자’로 변경한다.
- Firebase Authentication 계정을 삭제하고 user의 UID·이메일·비밀번호·이름·전화번호를 제거한다(이름 표시는 ‘탈퇴한 사용자’).
- 공유 기록의 외래키를 깨뜨리지 않도록 user_id와 최소 사용자 행 및 탈퇴 일시는 남긴다. 사용자 행까지 물리 삭제하는 기능은 아니다.
- 공유 채팅·메모 본문이나 첨부 파일에 직접 적힌 개인정보를 자동 탐지·편집하지는 않는다. 사용자 선택대로 공유 기록 본문은 유지한다.
- 실패 시 다음 검사에서 재시도한다. 외부 삭제는 중복 실행해도 안전하게 처리하며 MySQL 재검사로 이미 복구된 계정은 삭제하지 않는다.

## 개인 설정
- 아이디 저장·자동 로그인은 로그인 화면에서만 선택한다.
- 기기 푸시 토글은 기기별 저장이며 계정 전환·재실행 후에도 유지한다. 끄기는 서버 연결 해제 성공 후 반영한다.
- 꺼져 있으면 앱 복귀·토큰 변경으로 자동 등록하지 않는다. 다시 켤 때 OS 권한을 확인한다.

## DB / 검증
- 기존 withdrawn_at·left_at 사용. 테이블·컬럼 추가 없음.
- 테스트는 MySQL·Firestore·Firebase Auth를 모킹한다. 테스트 목적으로 실제 회원을 삭제하거나 30일 경과 worker를 실행하지 않는다.
- 기존 구현으로 이미 개인정보와 Firebase 계정이 삭제된 사용자는 이 변경으로 복원할 수 없다.
