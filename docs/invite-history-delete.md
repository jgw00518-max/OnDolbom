# 초대함 기록 삭제

사용자 확정: 수락·거절·취소·만료 기록만 개별/전체 삭제 가능. 대기·발송대기·발송실패는 삭제하지 않는다. 전체 삭제는 현재 탭의 처리된 기록만 대상으로 한다.

- 초대 원본의 invite_deleted_at을 변경하지 않는다. 상대방 기록·현재 가족 참여·미처리 초대의 효력을 유지한다.
- POST /invites/history/delete: side(received/sent)와 invite_ids(최대 400개). 서버가 발신자 본인/인증 계정 이메일 수신자 및 완료 상태를 다시 검사한다.
- Firestore invite_history_views/{사용자 해시}/hidden/{초대함·ID·발송시각 해시}에 개인별 목록 숨김을 저장한다. 재로그인·기기 변경 후에도 유지되며 다른 사용자/탭에는 영향이 없다. 새 초대 ID는 표시된다.
- 받은 목록에는 수락·거절·취소도 포함해 처리 이력을 확인·삭제할 수 있게 했다. 활성 대기 수에 따른 기존 배지 집계는 유지한다.
- 목록 조회 시 숨김 기록 확인에 Firestore 읽기가 추가된다. 새 MySQL 테이블·컬럼은 없다. API 서버 재시작이 필요하다.
- 화면에서 삭제 전 안내와 확인을 받고 빈 대상·처리 중에는 버튼을 비활성화한다. 여러 묶음 처리 중 실패하면 목록 재조회로 실제 결과를 확인하며 성공으로 위장하지 않는다.
- 받은·보낸 초대의 전체 삭제 버튼은 알림 화면과 같은 색상·크기·둥근 모양을 사용한다. 개별 휴지통은 각 카드 오른쪽 아래에 표시한다.
- 카드 오른쪽 위의 중복 날짜·시간 표시는 제거하고 본문의 보낸 시각·초대 생성 시각과 유효기간은 유지한다.
- 대기 항목의 휴지통을 눌러도 삭제 요청이나 자동 초대 취소를 수행하지 않고 안내만 표시한다. 발신자는 먼저 기존 초대 취소 절차를 완료해야 기록을 삭제할 수 있고, 수신자는 수락·거절하거나 발신자의 취소 이후 삭제할 수 있다. 발송대기·발송실패도 삭제를 막고 만료 기록은 삭제를 허용한다.
- 자동 검증: `flutter test test/invites_design_test.dart test/vm/invite_resend_test.dart`, `python -m unittest python.tests.features.test_invite_history_delete`. 서버·Firestore·SMTP는 모의 처리하며 실제 초대를 생성하거나 삭제하지 않는다.
