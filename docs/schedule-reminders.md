# 시작 72시간 전 재알림

## 동작 기준

- 담당자가 없는(`accepted_by IS NULL`) 미완료 일정만 대상으로 한다.
- 시작까지 **0시간 초과·72시간 이하**이면 현재 참여 중인 전체 가족에게 앱 내 알림을 발행한다.
- 일정 등록·변경이 확정되면 즉시 한 번 확인한다. 72시간보다 많이 남았으면 worker가 나중에 확인한다.
- 동일 일정의 동일 시작시간 버전에 한 번만 발행한다. 날짜나 시작시간이 바뀌면 새 버전으로 계산한다.
- 이름·메모·종료시간만 바뀌거나 재수락 응답 이력이 추가된 경우 중복 발행하지 않는다.
- 날짜·시작시간을 변경했다가 원래 시각으로 되돌려도 새 변경 버전으로 처리한다.
- 이미 발행한 버전이 수락 후 다시 미배정 상태가 되더라도 같은 재알림을 반복 발행하지 않는다.

## 실행: API와 worker 분리

API는 기본적으로 worker를 시작하지 않는다. 팀원 모두 프로젝트 루트에서 실행한다.

```powershell
python -m uvicorn python.main:app --host 0.0.0.0 --port 8000 --reload --no-access-log
```

알림 담당자만 별도 터미널에서 실행한다.

```powershell
python -m python.features.schedules.reminder_worker
```

동일한 MySQL·Firebase 프로젝트를 사용하면 하나의 worker가 모든 팀원의 푸시·72시간 재알림을 처리한다. 담당자 PC와 worker 터미널을 켜 두어야 한다. API 재시작과 별개로 동작하며 worker 종료는 해당 터미널에서 Ctrl+C로 한다. 종료되면 담당자가 다시 실행한다.

기존 터미널에 통합 실행을 설정했다면 서버를 종료하고 다음으로 해제한 뒤 재실행한다.

```powershell
Remove-Item Env:ONDOLBOM_REMINDER_WORKER -ErrorAction SilentlyContinue
```

이 설정은 `python/.env`가 아닌 실행 터미널의 환경 변수다. 기본값은 `0`이다. 기존 통합 실행은 `1`·`true`·`on`을 명시할 때만 활성화된다. 별도 worker와 통합 실행을 동시에 켜지 않는다. 테스트 후에도 `1`로 설정하지 않는다.

worker는 시작 직후 검사하고 재알림은 60초, 푸시는 작업이 있으면 5초·비어 있으면 최대 15초 간격으로 검사한다. `--once`는 한 번만 실제 검사하고 종료한다.

## 변경·수락·삭제 처리

별도 예약 테이블이나 고정 타이머를 만들지 않고 매번 최신 DB를 조회한다.
시작이 변경되면 이전 시각의 예약은 자동으로 대상에서 빠지고 새 시각을 기준으로 검사한다.
새 시작이 72시간 이하면 즉시 확인하며, 72시간 이후라면 해당 구간에 들어올 때 처리한다.
수락·완료·삭제된 일정, 삭제된 공간, 탈퇴·참여 종료 가족은 발행 대상에서 제외한다.
공간 → 일정 → 변경 이력 → 참여자 순서로 잠금 조회한 뒤 Firestore 발행까지 잠금을 유지한다.
이미 수락됐거나 시작시간 버전이 바뀐 과거 재알림은 목록·배지에서도 숨긴다.

Firestore `schedule_notifications`에 `schedule_reminder` 유형을 저장한다.
기존 색인과 읽음 처리를 재사용하며 MySQL 컬럼·테이블·마이그레이션은 추가하지 않는다.
시간은 DB의 `CURRENT_TIMESTAMP`와 저장된 일정의 날짜·시간을 비교한다. DB 시간대는 한국 시간이어야 한다.
발행 장애 시 일정 등록·변경은 유지하고 worker가 다음 검사 때 재시도한다.
발행 여부가 불확실한 경우도 같은 문서 ID로 재시도하며 기존 읽음 상태는 초기화하지 않는다.

## 확인

실제 DB·Firestore를 변경하지 않는 자동 테스트:

```powershell
python -B -m unittest python.tests.features.test_schedule_reminders
```

실제 앱에서는 테스트용 공간에서 확인한다.

1. 72시간보다 많이 남은 미배정 일정을 등록하면 등록 알림만 표시된다.
2. 시작까지 72시간 이하인 미배정 일정을 등록하면 등록 알림과 재알림이 각각 표시된다.
3. worker를 여러 번 실행해도 재알림이 추가되지 않는다.
4. 이름·메모·종료시간만 변경하면 재알림이 추가되지 않는다.
5. 시작을 다른 시각으로 바꾸고 72시간 이내이면 새 재알림이 표시된다.
6. 담당자가 수락하거나 일정·공간이 삭제되면 새 재알림이 발행되지 않는다.
7. 재알림을 열면 기존 일정 상세로 이동하며, 읽음 상태와 메뉴 배지도 갱신된다.

### 72시간 이내 신규 일정 등록

- DB 서버 시각 기준 시작까지 남은 시간이 0시간 초과~72시간 이하이면 일반 새 일정 등록 알림은 생성하지 않고 72시간 알림만 발행한다. 앱 내 알림과 FCM 푸시에 동일하게 적용한다.
- 72시간을 초과하면 기존 등록 알림을 발행하고, 이후 72시간 구간에 진입할 때 재알림을 발행한다.
- 재알림 장애 시 일반 등록 알림으로 대체하지 않으며, worker가 기존 재시도 방식으로 처리한다. 이미 발행된 과거 알림은 삭제하지 않는다.
