# 주보호자 이전 API

현재 주보호자가 같은 공간의 활성 일반 가족에게 즉시 역할을 이전한다.
기존 주보호자는 일반 가족으로 계속 참여한다. 상대방의 수락 절차는 없다.

## 요청·응답

```http
POST /family-room/{family_room_id}/transfer-representative
Authorization: Bearer <Firebase ID 토큰>
Content-Type: application/json
```

```json
{"target_user_id": "이전받을 가족의 내부 사용자 ID"}
```

공간 ID와 대상 사용자 ID는 공백 없는 1~50자다. 대상 ID의 앞뒤 공백은 제거한다.
요청자 ID·역할 등 다른 본문 필드는 허용하지 않는다. 요청자는 인증된 UID로 확인한다.
대상 사용자 ID는 기존 가족 목록 API가 반환하는 `user_id`를 사용한다.

성공 시 HTTP 200:

```json
{
  "result": "OK",
  "family_room_id": "공간 ID",
  "previous_representative_user_id": "기존 주보호자 ID",
  "representative_user_id": "새 주보호자 ID"
}
```

| 코드 | 의미 |
|---|---|
| 401 | 미인증·유효하지 않은 인증 토큰 |
| 403 | 현재 활성 주보호자가 아님, 요청자 계정 이용 불가 |
| 404 | 공간 없음 또는 소프트 삭제된 공간 |
| 409 | 본인 대상, 대상의 참여 종료·계정 탈퇴·다른 공간, 주보호자 상태 불일치 |
| 422 | 잘못된 ID, 본문 누락·형식 오류·추가 필드 |
| 503 | DB 연결·조회·갱신·commit 실패 |

## 권한·트랜잭션

- 공간 → 활성 참여 행 → 두 사용자 계정 순서로 `FOR UPDATE` 조회한다.
- 요청자는 `is_active=1`, `left_at IS NULL`, `is_representative=1`인 미탈퇴 사용자여야 한다.
- 활성 주보호자가 정확히 한 명인 경우에만 처리한다. 잘못된 다중 주보호자 상태는 자동 보정하지 않는다.
- 대상은 같은 공간에 활성 참여 중인 미탈퇴 일반 가족이어야 한다. 자기 자신에게 이전할 수 없다.
- 기존 주보호자를 0, 대상을 1로 갱신하고 함께 commit한다. 조건부 UPDATE가 한 행씩 처리되지 않거나 실패하면 모두 rollback한다.
- 같은 공간의 이전·탈퇴·강퇴·삭제 요청은 공간 행 잠금으로 직렬화한다. 동시에 두 이전 요청이 오면 먼저 확정된 요청 이후의 역할로 나머지 요청을 재검사한다.
- 기존 주보호자가 성공 응답을 받지 못해 재시도하면 현재 권한이 없어 403이 될 수 있다. 이전을 다시 실행하거나 성공으로 추측하지 말고 공간·가족 목록을 재조회한다.
- 동기 DB 작업은 기존 router의 `run_in_threadpool`에서 실행하고 모든 연결을 종료한다.

## 데이터 보존과 범위

- `participate.is_representative` 두 값만 변경한다.
- `family_room.created_by`는 최초 생성자 기록으로 보존한다.
- `joined_at`, `left_at`, 생성 컬럼 `is_active`와 다른 공간의 역할은 유지한다.
- 일정 배정·재수락 상태, 투약일지, 메모·채팅·이미지, 초대, 문의·답변 및 기존 알림을 변경하지 않는다.
- 두 사람 모두 계속 참여하므로 채팅 연결을 종료하지 않는다.
- 새 테이블·컬럼·마이그레이션, 이전 이력, 신규 알림·푸시를 추가하지 않는다.
- 기존 보호 API는 매 요청마다 DB 권한을 확인한다. 이전을 요청하기 전에 이미 권한 검사를 통과한 다른 요청까지 일괄 취소하는 기능은 없다.

## Flutter 연결

- 가족 공간 → 공간 설정 → 함께하는 가족 → 일반 가족의 `이전` 버튼으로 진입한다.
- 현재 활성 주보호자에게만 이전·강퇴 버튼을 표시하고 자기 자신은 대상에서 제외한다.
- 확인창에 대상의 이름·이메일, 기존 주보호자가 일반 가족으로 남으며 관리 권한을 잃는다는 설명을 표시한다.
- 취소하면 요청하지 않는다. 이전 중에는 중복 제출·취소·시스템 뒤로가기를 차단한다.
- 기존 인증 토큰과 공간 API 클라이언트로 요청한다. 토큰 대기·응답 수신 후에도 계정·공간·현재 역할을 재검사한다.
- 성공 응답의 공간·이전 전/후 사용자 ID가 요청과 일치하는지 확인한다.
- 성공한 직후 요청자의 로컬 참여 역할을 일반 가족으로 변경해 관리 버튼을 숨기고 공간·가족 목록을 재조회한다. 공간 재조회 실패 시에도 확정된 일반 가족 역할과 다른 공간 정보는 보존한다.
- 실패 시 확인창과 오류 문구를 유지한다. 시간 초과나 응답 이상은 성공으로 가정하지 않고 목록 새로고침을 안내한다.
- 가족 목록 상단 새로고침 버튼은 공간 권한과 가족 목록을 함께 갱신한다. 이전받은 가족의 다른 기기도 재조회하면 새 역할을 확인할 수 있다. 원격 기기에 역할 변경을 즉시 전달하는 신규 푸시는 추가하지 않는다.

## 검증

```powershell
$env:ONDOLBOM_REMINDER_WORKER = '0'
python -m unittest python.tests.test_representative_transfer python.tests.test_family_membership python.tests.test_family_room_delete
flutter test test/representative_transfer_test.dart test/family_membership_test.dart test/space_settings_test.dart test/family_room_delete_test.dart
```

인증·입력·대상과 요청자 상태·조건부 갱신 실패·rollback·연결 정리·채팅 유지 및 동시 요청을 대체 DB/잠금으로 검증한다.
실제 스키마의 컬럼·인덱스만 읽기 전용으로 확인했으며, 공유 DB의 역할이나 원본 기록을 테스트 목적으로 변경하지 않는다.
Flutter는 모의 HTTP·인증으로 확인창 취소·성공·실패·중복 제출, 재조회, 권한과 계정·공간 변경 및 작은 화면·큰 글씨를 검증한다.
실제 MySQL 동시 트랜잭션과 두 앱의 역할 갱신은 별도 연동 확인 대상이다.
