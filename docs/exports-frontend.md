# Flutter 메모·채팅 내보내기

## 화면과 사용 순서

현재 가족 공간 홈의 맨 아래, 오늘의 일정 카드 다음에 `메모·채팅 내보내기` 버튼을 둔다.
주보호자와 일반 가족 모두 같은 버튼을 사용하며 실제 접근 권한은 서버가 확인한다.

1. 가로로 배치된 시작일·종료일 칸을 각각 눌러 달력에서 선택한다.
   기본 기간은 이번 달 1일~오늘이다. 종료일은 오늘 이후를 선택할 수 없으며,
   시작일은 종료일 이하, 종료일은 시작일 이상으로 선택 범위를 제한한다.
2. 메모·채팅 체크박스로 하나 이상 선택한다. 기본은 둘 다 선택이다.
3. 이미지 포함 여부는 `포함`·`제외` 라디오 버튼 중 하나를 선택한다. 기본은 제외다.
4. 파일 형식 라디오 버튼에서 `HTML`·`PDF` 중 하나를 선택한다. 기본은 HTML이다.
   HTML은 문서·이미지를 묶은 ZIP으로, PDF는 문서 한 개로 다운로드한다.
   투약 정보·투약일지 제외 안내를 확인하고 `파일 생성`을 누른다.
5. 서버 응답 대기 중 생성 중 표시와 중복 요청 방지를 적용한다.
6. 생성 완료 후 `파일 다운로드`를 누르면 시스템 저장 창을 통해 선택한 형식의 파일을 저장한다.
   웹은 브라우저 다운로드를 시작하며 브라우저 다운로드 목록에서 결과를 확인한다.
7. 생성 실패 시 서버 사유와 `다시 요청`을 표시한다. 날짜·선택 옵션은 유지한다.
   저장 실패·취소 시 생성한 파일로 다시 저장할 수 있다.

옵션 변경 시 기존 생성 결과를 지워 이전 옵션의 파일을 저장하지 않게 한다.
계정·공간 변경 후에는 이전 화면에서 요청·파일 노출·저장을 차단한다.
API 호출 전후 및 저장 전후에 현재 계정·공간을 확인한다.
화면이 닫히면 자동 해제되는 provider가 다운로드 결과를 정리한다.

## 저장 오류 안내와 진단

저장 실패는 생성 실패와 구분하며, 파일명과 다운로드 버튼 위에 원인별 문구를 빨간색으로 표시한다.
실패해도 생성한 ZIP/PDF는 유지하여 다운로드 버튼으로 다시 저장할 수 있다.
재시도에 성공하거나 옵션을 변경하면 이전 오류를 초기화한다.

| 구분 | 표시하는 안내 |
| --- | --- |
| `MissingPluginException` | 파일 저장 기능을 사용할 수 없어요. 앱을 완전히 종료한 뒤 다시 실행해 주세요. 계속되면 앱을 업데이트해 주세요. |
| 접근 권한 없음 | 선택한 위치에 저장할 수 없어요. 다른 폴더를 선택해 주세요. |
| 저장 공간 부족 | 선택한 저장 위치의 공간이 부족해요. 공간을 확보하거나 다른 위치를 선택해 주세요. |
| 위치 없음·사용 불가 | 선택한 저장 위치를 사용할 수 없어요. 다른 위치를 선택해 주세요. |
| 저장 창 열기 실패 | 파일 저장 창을 열 수 없어요. 앱을 다시 실행하거나 기기의 파일 앱을 확인해 주세요. |
| 이미 열린 저장 창 | 파일 저장 창이 이미 열려 있어요. 현재 창을 닫은 뒤 다시 시도해 주세요. |
| 원인 불명 | 파일을 저장하지 못했어요. 저장 위치를 바꾸거나 다시 시도해 주세요. |

취소는 오류가 아니며 기존 취소 안내를 표시한다.
분류는 플러그인 코드, 네이티브 메시지의 명시적인 `ENOSPC`·`EACCES`·`ENOENT` 등의 식별자,
파일 시스템 예외의 OS별 번호를 사용한다. Android의 `Error while saving file`,
iOS의 `Failed to write file`처럼 일반적인 쓰기 실패 코드만으로는 공간 부족 등을 추정하지 않는다.
플러그인이 세부 원인을 전달하지 않으면 원인 불명 안내를 사용한다.

개발자 진단은 Dart `developer.log`의 `ondolbom.exports.save` 항목으로 남긴다.
분류명·예외 타입·정규화한 코드·스택을 기록하며, 원본 메시지·details·선택한 파일 경로·파일 내용은 기록하지 않는다.
Flutter DevTools 등의 연결된 개발 로그에서 확인할 수 있으며 별도 파일이나 외부 서버에 영구 저장하는 기능은 아니다.
플러그인 누락이 설치된 APK의 네이티브 코드 누락이라면 개발 환경에서 중지 후 재빌드·설치가 필요하다.

## API와 파일 저장

VM이 `familyContextProvider`의 선택 공간과 `apiTokenLoaderProvider`의 Firebase ID 토큰을 사용해
`POST /exports/download`를 호출한다. 요청 본문은 [API 안내](exports-api.md)를 따른다.
토큰 조회 시간 제한은 15초, 파일 생성·수신 시간 제한은 3분이다.
시간 초과는 서버 작업의 즉시 취소를 의미하지 않는다.

HTML은 `format: html_zip`·`Accept: application/zip`, PDF는 `format: pdf`·`Accept: application/pdf`로 요청한다.
선택한 형식의 콘텐츠 타입과 시작 서명(ZIP: `PK`, PDF: `%PDF-`)을 확인하며,
잘못된 형식의 응답은 저장하지 않는다. 수신 바이트와 요청 날짜·형식으로 만든 `.zip`/`.pdf` 파일명을 화면 상태에 보관한다.
파일 형식을 바꾸면 기존 생성 결과를 지우고, 생성·저장 중에는 형식을 바꿀 수 없다.
전체 파일을 메모리에 수신하므로 큰 파일은 기기 메모리와 요청 시간의 영향을 받는다.
작업 이력과 앱 재시작 후 이어받기는 제공하지 않는다.

`file_picker 10.3.10`의 `saveFile(bytes: ...)`을 사용한다.
현재 프로젝트의 iOS 13 대상 버전을 유지하면서 Android·iOS·데스크톱의 저장 창과 웹 다운로드를 연결한다.
새 플러그인을 추가했으므로 실행 중인 앱은 완전히 종료한 뒤 다시 빌드·실행한다.
HTML은 압축을 해제하고 `index.html`을 열며, PDF는 PDF 뷰어에서 바로 열면 된다.
파일 저장 창의 확장자도 선택한 형식(`zip` 또는 `pdf`)에 맞춘다.

## 코드와 검증

| 파일 | 역할 |
| --- | --- |
| `lib/model/exports/export_options.dart` | 요청 옵션·날짜 직렬화·파일 데이터 |
| `lib/vm/exports/export_vm.dart` | 인증 API 요청·상태·ZIP/PDF 수신·파일 저장·오류 변환 |
| `lib/vm/exports/export_save_failure.dart` | 저장 실패 원인 분류·사용자 안내 |
| `lib/vm/exports/export_os_error_*.dart` | OS별 파일 시스템 오류 코드·웹용 대체 구현 |
| `lib/view/exports/export_view.dart` | 기간·범위·이미지 옵션·생성·다운로드 화면 |
| `lib/view/family_room/family_room_home.dart` | 가족 공간 맨 아래 진입 버튼 |
| `test/export_test.dart` | API 옵션·저장 재시도·권한 변경·날짜 상한·화면 연결 검증 |
| `test/export_save_failure_test.dart` | 플러그인·OS 오류 분류·모호한 오류의 일반 안내·개인정보 비노출 |

```powershell
flutter pub get
flutter analyze --no-pub
flutter test --no-pub test/export_test.dart test/export_save_failure_test.dart
```

테스트에서는 HTTP와 파일 저장기를 대체한다. 실제 Android·iOS의 파일 저장 창과
Firebase·MySQL을 연결한 ZIP/PDF 다운로드는 기기에서 별도로 확인해야 한다.
