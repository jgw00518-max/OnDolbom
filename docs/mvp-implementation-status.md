# 메모·투약일지 MVP 구현 현황

갱신일: 2026-10-23 (KST)

대상 브랜치: `feature/memos-medications-mvp`.
이 문서는 현재 코드와 이번 커밋 범위를 기준으로 구현·미연결·미구현 상태를 구분합니다.
기존 `d1d5f64` 기준 보고서에서 메모 테마 통일, 투약일지 작성 API와 프론트엔드 구현을 반영했습니다.

## 1. 개발 환경과 담당 범위

- 프론트엔드: Dart / Flutter / Riverpod
- 백엔드: Python / FastAPI / PyMySQL
- DB: MySQL
- 서버 실행: 가상환경 없이 프로젝트 루트에서 `python python/main.py`
- 담당 MVP: 메모 작성·조회, 투약 정보 작성·수정·조회, 가족 공동 체크리스트, 공간별 텍스트 채팅

## 2. 기능별 상태

## 4. 구현된 API

| 메서드 | 경로 | 주요 입력 | 성공 응답 |
| --- | --- | --- | --- |
| GET | `/health` | 없음 | `{"status":"ok"}` |
| GET | `/memos/select` | 공간 ID, limit, offset | `{"results":[...]}` |
| POST | `/memos/insert` | 공간 ID, 메모 내용 | HTTP 201, result, memo_id |
| GET | `/medications/select` | 공간 ID, 선택적 투약 날짜, limit, offset | `{"results":[...]}` |
| POST | `/medications/insert` | 공간 ID, 약 정보, 날짜, 시간, 용량, 단위 | HTTP 201, result, medication_log_seq |

조회 기본 20개, 최대 100개이며 삭제된 기록과 공간을 제외합니다.
빈 목록은 성공 응답의 빈 배열로 반환합니다. `/health`는 DB·인증 확인을 수행하지 않습니다.

메모 내용은 공백 제거 후 1~10,000자, UUID·작성 시간·좋아요 초기값은 서버/DB가 생성합니다.
투약 정보는 100자, 시간과 단위는 20자 이내이며 용량은 양수·정수부 7자리·소수부 3자리 이내입니다.
투약일지 번호는 DB 자동 증가 값, 기록 시각은 DB 기본값이고 투약 확인 시각은 null입니다.
쓰기 작업은 요청별 같은 연결에서 참여 확인 행을 잠근 뒤 저장하고, 성공 시 한 번 commit,
실패 시 rollback합니다. 커서는 with 문, 연결은 finally로 정리합니다.

## 5. 인증·권한과 실제 연동 상태

메모 조회·작성과 투약일지 조회·작성은 공통 `get_current_user_id`를 사용합니다.
이 의존성은 서버의 `request.state.user_id`를 읽는 연결 지점이며 토큰 검증 코드가 아닙니다.
현재 브랜치에는 로그인 토큰 검증과 state 설정 코드가 없어 실제 요청은 401입니다.
실행 옵션이나 요청 본문의 사용자 ID를 전달해도 인증을 대신하지 못합니다.

인증 이후에도 `participate`에서 사용자·공간 일치, `is_active = 1`, `left_at IS NULL`,
공간 미삭제, 사용자 미탈퇴를 검사하며 위반 시 403을 반환합니다.
작성자는 인증된 사용자로 결정합니다. 입력 오류는 422, 내부 DB 오류는 상세 정보를 숨긴 500입니다.

투약일지 VM에는 `apiTokenLoaderProvider`를 연결하면 유효한 토큰을 Bearer 헤더에 넣는 처리가 있습니다.
메모 VM의 토큰 전달은 아직 연결하지 않았습니다. 기존 본문의 `user_id`는 메모 서버에서 무시합니다.
별도 [로그인·회원가입 PR #1](https://github.com/jgw00518-max/OnDolbom/pull/1)의 설명에는
Firebase 인증·FastAPI 토큰 검증·프로필 API가 있으나 이 브랜치에는 아직 통합하지 않았습니다.
연동 시 실제 인증 함수의 계약과 Firebase UID→MySQL 사용자 ID 매핑을 확인해야 합니다.

## 6. 홈 연결과 커밋 제외 범위

로컬 `lib/view/home.dart`에는 메모·투약일지로 들어가는 돌봄 메뉴가 구현되어 있습니다.
다만 기존 사용자 요청에 따라 홈 파일은 이번 커밋에 포함하지 않습니다.
`lib/main.dart`와 루트 `README.md`도 커밋 대상에서 제외합니다.
따라서 커밋만 체크아웃한 환경에서는 기존 홈 또는 라우트에 각 목록 화면을 연결해야 합니다.
테스트는 앱 테마를 읽되 기능 화면을 직접 실행하여 제외된 홈 구현에 의존하지 않습니다.

`familyContextProvider`는 현재 실행 옵션의 공간·사용자 정보를 읽는 임시 공통 상태입니다.
메모 provider는 이 상태의 별칭입니다. 실제 로그인·공간 선택 상태를 연결하는 작업이 남아 있습니다.
앱 실행 옵션과 플랫폼별 서버 주소는 상세 문서를 참고합니다.
DB 접속값·`.env`·Firebase 비공개 키는 문서와 커밋에 포함하지 않습니다.
