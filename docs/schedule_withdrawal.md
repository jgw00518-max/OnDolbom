# 담당 가족의 일정 참여 취소 — 2026-10-29

## B 구현 범위

현재 담당 가족이 자신의 미완료 일정 참여를 철회한다. 가족 공간 탈퇴와 구분하며 가족 참여는 유지한다. 재수락 대기 중에는 기존 거절 흐름을 사용한다. 시작 시각에 따른 추가 제한은 이번 요청에서 정하지 않았으므로 새로 도입하지 않았다.

- 일정 상세: 현재 본인 담당·미완료·재수락 대기 아님인 경우 `일정 참여 취소` 버튼 표시. 코랄색 버튼과 취소/철회 확인창, 중복 누름 방지 및 서버 재조회.
- `POST /schedules/{schedule_seq}/withdraw`: Firebase 인증과 현재 참여를 확인하고 공간 → 일정 순서로 잠금. 본인 배정·미완료·삭제 여부·화면의 최신 이력 번호 및 수락 시각을 검증한다.
- 본문: `expected_history_seq`(최초 수락으로 이력이 없으면 null), `expected_accepted_at`(월별 조회의 accepted_at). 오래된 화면이나 중복 요청은 409로 재조회 안내한다.
- `create_schedule.accepted_by`, `accepted_at` 해제. 최신 일정 내용을 보존한 새 `update_schedule` 행을 생성하며 changed_by는 철회자, 담당자/수락시각은 NULL이다. DB 컬럼은 추가하지 않는다.
- 알림 준비 실패 시 rollback. DB commit 후 발행 실패 시 철회는 유지하고 기존 재수락 worker에서 pending 재시도한다.
- 자동 처리 검수와 달리 참여 철회 API는 사용자 버튼 요청으로 실행되므로 worker 없이 즉시 처리된다. worker는 발행 실패 재시도에 사용한다.

## A 인수인계 — 주보호자 참여 취소 전용 알림 연결 필요

사용자는 이번 범위를 **B 버튼·철회 API·알림 발행·A 인수인계 문서까지**로 지정했다. A 담당 공통 모델·푸시 파일은 수정하지 않았다.

| 유형 | 문서 ID | 수신자 | 안내 |
| --- | --- | --- | --- |
| schedule_withdrawn | schedule_withdrawn_{schedule_seq}_{history_seq} | 현재 주보호자 | actor_name 가족이 일정 참여를 철회했음을 안내 |
| schedule_recruitment | schedule_recruitment_{schedule_seq}_{history_seq} | 철회자를 포함한 현재 전체 참여 가족 | 담당 가족 재모집 안내 |

두 이벤트의 `reason=participation_withdrawal`, `former_assignee_id`는 철회한 가족 ID다. 일정 전체 가족 재모집을 위해 actor_id 자동 제외는 적용하지 않는다. 문서 준비 시 확정한 recipient_ids를 유지한다. 알림의 `history_seq`는 새 철회 처리 이력이다.

A 연결 사항:

1. `visible_v2()`에 schedule_withdrawn 허용. 공통 앱 모델의 전용 제목과 아이콘·푸시 대상·문구·라우팅 추가. 기본 신규 일정 제목으로 표시하지 않는다.
2. 기존 `_visible()`는 request_history_seq 없는 재모집을 주보호자에게 schedule_declined로 바꾼다. `reason=participation_withdrawal`은 재수락 거절이 아니므로 이 변환에서 제외해야 한다. 주보호자는 철회 안내와 전체 가족 재모집 안내를 각각 받는다.
3. 목록/배지는 같은 허용 기준을 사용하고 문자열 ID·개별 읽음 상태 유지. 알림 클릭은 월별 최신 Schedule을 조회해 기존 상세로 연결한다.
4. 기존 schedule_recruitment는 공통 푸시 대상이지만 정확한 철회/재모집 문구, 새 schedule_withdrawn 기기 수신은 A가 연결·검수한다. Firestore published와 앱/푸시 도착을 구분한다.

## 수동 검수 순서

1. 서버 재시작과 Flutter Hot Restart 후 다른 일정과 겹치지 않는 새 테스트 일정 생성, test3 수락.
2. test3에게만 철회 버튼이 보이는지 확인. test4 및 주보호자는 버튼 없음.
3. 철회 확인창에서 취소 → 담당자 유지. 다시 철회 실행 → 담당자 모집 중, 최신 일정명·메모·시간 유지. 가족 공간에는 계속 참여 중.
4. test4가 수락 → 담당자 test4. test3의 이전 화면으로 철회 요청 시 409, test4 배정 유지.
5. Firestore에 같은 철회 이력의 schedule_withdrawn(주보호자)과 schedule_recruitment(전체 가족) published 및 수신자 확인.
6. A 연결 이후 주보호자 철회 안내/전체 재모집, 읽음·배지·푸시와 알림 상세 이동 검수.

실제 공유 DB 데이터는 구현 도구로 임의 변경하지 않았다. 앱·Firestore 실제 검수는 위 순서로 사용자가 진행한다.


## 자동 검증 결과

참여 철회 10개와 기존 이름·메모 비교/만료 알림/월별 조회 16개, 총 26개 통과. Flutter 변경 3개 파일 분석 통과. 사용자가 서버 재시작 후 참여 취소 처리와 재모집 알림 표시를 확인했다. 주보호자 전용 안내, Firestore 수신자·발행 상세와 후속 재수락 검수는 별도이다. commit·push는 이번 요청으로 실행하지 않았다.


## 사용자 확인 결과와 다음 GitHub PR 전달 사항

- 실제 앱에서 `일정 참여 취소` 실행 성공과 담당 가족 재모집 알림 표시를 확인했다. 초기 Not Found는 API 서버가 이전 코드를 실행한 상태였으며 서버 재시작 후 해결했다.
- 주보호자에게 “담당 가족이 일정 참여를 취소했습니다”라는 **전용 안내를 앱에 표시하는 연결은 아직 A 작업으로 남아 있다.** B는 schedule_withdrawn 이벤트 준비·발행 코드를 구현했다. 전용 앱 안내 미연결과 서버 이벤트 미구현을 혼동하지 않는다.
- A는 schedule_withdrawn의 V2 필터, 제목/아이콘, 읽음·배지, 푸시 대상·문구·라우팅을 연결한다. 수신자는 현재 주보호자이며 actor_name으로 취소한 가족을 안내한다.
- 재모집 알림은 전체 참여 가족 대상이며 reason=participation_withdrawal이다. 주보호자 화면에서 기존 schedule_declined(재수락 거절)로 잘못 바꾸지 않도록 분기한다.
- 다음 PR은 이 후속 기능을 앞선 525a3f6 커밋의 기존 작업과 구분하여 포함한다. 커밋/업로드 전 아래 인수인계 문서와 신규 파일 누락을 확인한다.


### 참여 취소 시 24시간 미만 안내

미래 일정의 시작까지 24시간 미만 남은 경우 참여 취소 확인창에 주보호자에게 연락해 새 담당 가족을 찾도록 요청하는 안내를 추가했다. 정확히 24시간 이상 또는 이미 시작한 일정에는 이 사전 안내를 표시하지 않는다. 앱 기기의 현재 시각과 표시된 일정의 시작 시각으로 판단한다. 안내 추가이며 취소 제한·승인·새 알림 수신자 정책을 도입하지 않는다. 서버는 계속 현재 배정과 최신 이력을 검증한다.
