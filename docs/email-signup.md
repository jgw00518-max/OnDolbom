# 회원가입 이메일 인증번호

이메일·비밀번호 가입은 이메일 입력 → 인증번호 전송 → 이메일에서 번호 확인 → 앱에서 코드 입력 → 비밀번호와 확인 입력 → 가입·로그인 → 이름·전화번호 등록 순서다.
Google·카카오·네이버 로그인 흐름에는 이번 인증 단계를 추가하지 않는다.

## 설정

[비밀번호 재설정](account-recovery.md)과 동일한 `SMTP_*` 및 `PASSWORD_RESET_SECRET` 설정을 재사용한다. 가입용 발신 계정이나 비밀값을 별도로 만들 필요는 없다.
각 팀원은 같은 비밀값과 Firebase 프로젝트를 사용하고 각자 로컬 서버의 `.env`를 구성한다. SMTP 연동과 실제 메일 수신 검증은 가족 초대 발송 기능을 합친 뒤 진행한다.
현재 SMTP 미설정 상태에서는 발송 요청에 503이 반환되며 인증을 건너뛰어 가입할 수 없다.

Firestore 규칙에는 `firestore.rules`의 `signup_challenges`, `signup_limits` 차단 규칙을 병합한다. 기존에 전체 경로를 허용하는 규칙이 있다면 제거/제한해야 한다. 앱은 인증 컬렉션에 직접 접근하지 않는다.
서버 Admin SDK가 이메일 소유 확인 후 `email_verified=True`인 Firebase 계정을 생성한다. 앱은 이어서 이메일·비밀번호로 로그인하고 기존 프로필 등록 화면을 표시한다.
MySQL 테이블·컬럼은 변경하지 않는다. 비밀번호 원문은 DB·Firestore·로그에 저장하지 않는다. 운영 환경은 HTTPS를 사용한다.

## API

| API | 요청 | 성공 응답 |
| --- | --- | --- |
| `POST /auth/signup/request` | `email` | `request_id`, `expires_in: 600`, `retry_after: 60` |
| `POST /auth/signup/verify` | `email`, `request_id`, `code` | `verification_token`, `expires_in: 300` |
| `POST /auth/signup/confirm` | `email`, `request_id`, `verification_token`, `password` | `created: true` |

- 인증번호는 6자리, 10분 유효, 최대 5회 오입력 허용이다.
- 이메일별 60초 재발송 간격·시간당 5회, 직접 연결 IP별 시간당 30회로 제한한다. 재발송하면 이전 코드·가입 토큰은 무효다.
- 가입 증명은 이메일에 연결된 일회용 토큰이며 5분 유효하다. 인증번호 확인 전에는 Firebase 계정을 생성하지 않는다.
- 비밀번호는 6~128자로 받는다. 앱은 확인 입력까지 일치해야 가입 요청한다.
- 인증번호와 토큰은 해시로 저장하고, 가입용·재설정용 컬렉션은 분리한다. 한 용도의 증명을 다른 용도로 쓸 수 없다.
- 이미 존재하는 이메일에는 가입 코드를 보내지 않고 동일한 발송 요청 응답을 준다. 기존 계정은 로그인·비밀번호 재설정을 이용한다. 계정을 덮어쓰거나 소셜 계정에 비밀번호를 추가하지 않는다.
- 인증 중 다른 요청으로 같은 이메일이 가입되면 최종 계정 생성 시 409를 반환한다.
- 토큰 소비 후 Firebase 계정을 생성한다. 서버 실패·응답 유실 시에는 로그인 가능 여부를 확인하고 필요하면 가입 인증을 처음부터 진행한다. 서버가 생성한 계정을 자동 삭제하거나 기존 계정을 수정하지 않는다.
- 앱 종료·화면 이탈 시 인증 상태가 사라진다. 다시 진입해 인증을 요청한다.
- Firebase 클라이언트 SDK를 직접 호출해 미인증 계정을 만든 경우에도 이메일·비밀번호 토큰의 `email_verified`가 true가 아니면 새 MySQL 가족 프로필 등록을 403으로 막는다. 기존에 프로필 등록까지 완료한 계정의 로그인은 유지한다.

## 실제 검증

1. SMTP 통합 후 미가입 이메일로 가입 화면을 연다.
2. 받은 번호로 인증을 완료하기 전에는 비밀번호 입력·최종 가입 단계로 갈 수 없는지 확인한다.
3. 잘못된 번호·만료·재전송 이전 코드·5회 오입력·다른 이메일의 증명을 거절하는지 확인한다.
4. 가입 완료 후 Firebase의 이메일 인증 여부와 이름·전화번호 입력 화면을 확인한다.
5. 프로필 등록 후 로그아웃하고 이메일·비밀번호로 다시 로그인한다.
6. 기존 이메일·소셜 계정은 수정되지 않는지 확인한다.

자동 테스트는 메일/Firebase/Firestore를 대체한다. SMTP 수신·실제 Firebase 계정 생성·다중 서버 동시성은 별도 검증 대상이다.

참고: [Firebase Admin 사용자 생성](https://firebase.google.com/docs/auth/admin/manage-users).
